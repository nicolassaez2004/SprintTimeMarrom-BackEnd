O serviço reutiliza `Linha` e `VersaoGTFS` das dependências US02. A chave
composta impede ligar uma importação a uma linha de outra versão GTFS.
`ImportacaoProgramacao` é uma extensão operacional ao diagrama: agrupa a
procedência e registra uma captura válida mesmo quando ela não tem partidas.
`PartidaProgramada` expõe linha, data, sentido, fonte e versão por essa relação,
além de persistir a saída prevista, o tipo de oferta e o intervalo.

A versão GTFS identifica o contexto da rede; **não transforma a origem oficial
em GTFS**. Para importações deste cartão, `fonte=OFICIAL`, `tipo_oferta=FIXA` e
`intervalo_seg=NULL`. A migração admite a categoria de frequência prevista no
diagrama, mas este cartão não gera partidas por frequência.

Nenhuma rotina inicia com a API, cria tabelas automaticamente ou executa tarefas
periódicas. O frontend não recebe acesso direto ao banco.

## Regras de normalização e procedência

- Linha: código completo, como `3762-10` ou `175T-10`; seleção exata e única
  no catálogo, sem confundir variantes `-10` e `-21`.
- Sentido: `ida/0` e `volta/1`, conforme a convenção GTFS adotada no repositório.
  Não enviar diretamente os códigos de sentido `1/2` do Olho Vivo.
- Data operacional: informada explicitamente como `date`; o tipo de dia também
  é obrigatório (`UTIL`, `SABADO`, `DOMINGO`, `FERIADO`). Não se deduz o calendário
  operacional pelo dia da semana.
- Saídas: interpretadas em `America/Sao_Paulo`, persistidas/devolvidas em UTC.
  Aceita `HH:MM`, `HH:MM:SS` e horas acima de 24. Preserva a data operacional
  mesmo quando a saída ocorre na madrugada seguinte. Preserva saídas simultâneas.
- Para horários de relógio que passam de 23h para 00h, admite uma única virada
  na sequência noturna (18h–23h59 para 00h–05h59). Outras desordens, múltiplas
  viradas ou mistura ambígua com horas acima de 24 são rejeitadas para revisão.
  Essa convenção precisa ser conferida com uma captura real.
- A URL de origem, os instantes de primeira captura e última verificação, o
  JSON original e seu hash ficam associados ao lote e podem ser recuperados.
  `versao_fonte` é SHA-256 dos bytes originais; não é uma versão ou data de
  publicação declarada pela SPTrans. O hash comprova integridade do conteúdo,
  sem comprovar por si só a autenticidade de uma captura fornecida manualmente.
- Reimportação do mesmo contexto e hash não duplica partidas. Conteúdo diferente
  cria outra versão, preservando o histórico. A consulta padrão escolhe a versão
  verificada mais recentemente; `versao_fonte` permite recuperar a anterior.
- A captura e todas as partidas são confirmadas em uma transação. Rollback SQL
  preserva o objeto bruto, permitindo repetição segura sem apagar um arquivo
  que outro processo possa estar usando.

O script do portal contém ajustes específicos para o feriado de 20/11 e outras
exceções de linhas. O importador lê o JSON de origem e **não reproduz esses ajustes
da interface nem promete equivalência com a grade exibida em feriados**. Se não
há grupo explícito de feriado, devolve `FERIADO_NAO_PUBLICADO`. Validar calendário
e exceções com a fonte oficial antes de aceitar a programação para essas datas.

## Indisponibilidade e caminho de fallback

Falha de rede, HTTP diferente de 200, linha ausente/ambígua, JSON inválido ou
feriado não publicado acionam `preparar_fallback_gtfs`. O resultado informa:

```json
{
  "estado": "FALLBACK_GTFS_NECESSARIO",
  "oficial_disponivel": false,
  "motivo": "HTTP_403",
  "linha": "3762-10",
  "sentido": "0",
  "data_operacao": "2026-11-19",
  "tipo_dia": "UTIL",
  "fallback": {
    "fonte": "GTFS",
    "estado": "PENDENTE_GERACAO",
    "versao_gtfs_id": "identificador da versão vigente"
  },
  "partidas": []
}
```

O serviço resolve a versão GTFS e a existência da linha para preparar o
encaminhamento. Pré-requisitos ausentes são explícitos: `SEM_VERSAO_GTFS`,
`VERSAO_GTFS_AMBIGUA` ou `LINHA_NAO_IMPORTADA`. Não escolhe arbitrariamente uma
versão quando as vigências se sobrepõem; uma versão explícita pode ser informada
e sua vigência continua sendo validada.

O consumidor deve encaminhar esse contexto ao gerador GTFS da continuação da
US04 e identificar a oferta resultante como `GTFS`, preservando sua versão.
**A geração automática de partidas a partir do GTFS não está implementada neste
cartão nem existia no repositório.** `PENDENTE_GERACAO` é um encaminhamento,
não uma oferta GTFS calculada. Até integrar o gerador, a resposta permanece
explícita, sem partidas inventadas e sem retornar sucesso de importação.

Uma resposta estruturalmente válida com zero partidas para o dia solicitado é
uma captura oficial vazia, não uma falha da fonte. Falhas não apagam capturas
anteriores. A consulta de histórico devolve `ARMAZENADA` e não afirma que a fonte
continua disponível no momento. Motivo e estado de fallback também vão ao log.

## Uso após o responsável preparar o banco

Instalar `requirements.txt`; `tzdata` fornece os fusos no Windows. A configuração
opcional `PROGRAMACAO_STORAGE_DIR` define onde guardar os JSONs; o padrão é
`instance/programacao`. Esse diretório deve acompanhar o banco em backups e
estar acessível a todos os consumidores. Arquivos brutos ficam fora do Git.

O responsável pelas migrações deve revisar a `0008`, conferir as dependências
até a `0007` e aplicar pelo fluxo do time. **Nenhuma migração foi executada no
Aiven por este trabalho.** Importar também requer linha e versão carregadas
pelas tarefas US02; banco vazio não satisfaz essas pré-condições.

Com o ambiente virtual ativo e o banco preparado, na pasta do backend:

```powershell
python -m app.programacao importar --linha 3762-10 --sentido ida --data 2026-11-19 --tipo-dia UTIL
python -m app.programacao consultar --linha 3762-10 --sentido ida --data 2026-11-19 --tipo-dia UTIL
```

Se o time obtiver uma captura JSON **real e autorizada** no formato de detalhe
descrito acima, também é possível importá-la com procedência declarada:

```powershell
python -m app.programacao importar --linha 3762-10 --sentido ida --data 2026-11-19 --tipo-dia UTIL --arquivo-json captura-oficial.json --fonte-url https://itinerariosapi.sptrans.com.br/BuscarDetalheLinhaTeste
```

`--versao-gtfs ID` seleciona explicitamente o contexto de rede, inclusive para
consulta histórica. `consultar --versao-fonte HASH` recupera um conteúdo anterior.
No Python, usar `importar_oficial`/`consultar_oficial` em contexto Flask.
O JSON de saída inclui as partidas e a procedência comum a todas elas.

Códigos de saída: `0` para importação/repetição/consulta encontrada; `2` para
fallback necessário ou captura não importada; `1` para erro de pré-condição,
arquivo ou banco. A ferramenta não imprime a URL de conexão nem as senhas.
