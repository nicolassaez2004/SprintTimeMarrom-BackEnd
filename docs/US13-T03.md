# US13-T03 — exibir o relatório e conferir falhas conhecidas

Criada em 17/11/2026. Iniciada em 23/11/2026. Implementação e revisão técnica:
Codex, pronta para commit e Review. Frontend e backend na branch `US13-T03`,
sem commit nem publicação de branch por esta entrega.

## O que abrir

Frontend: **`http://127.0.0.1:5173/qualidade.html`**. A tela usa a API pública
`GET /api/qualidade?inicio=AAAA-MM-DD&fim=AAAA-MM-DD&janelas=true`.

No repositório backend, ativar um ambiente com `requirements.txt` instalado
e executar `python app.py`. No frontend, executar
`python -m http.server 5173 --bind 127.0.0.1`. O frontend não recebe senhas,
token SPTrans ou acesso direto ao MySQL. O endereço da API é configurado
no meta `api-base` de `qualidade.html`.

Como a main do frontend só tinha README, a tela foi adicionada em arquivo
próprio, seguindo cores/tipografia da branch `exemplo`, sem importar as
outras telas fictícias nem criar um framework diferente. Não há npm install
para servir a página. Os testes usam Node 20+.

## Comportamento

- Período de até 31 dias e navegação por cada dia retornado.
- Contadores diários, legenda e 96 blocos de 15 minutos; navegação por teclado.
- Cada lacuna mostra o trecho no dia e o início/fim reais do evento.
  O fim do dia aparece como **24:00**, evitando confundir um dia inteiro
  sem dados com um intervalo 00:00–00:00 de duração zero.
- Lacuna aberta continua com `fim: null`; o trecho visível termina no instante
  observado, sem inventar encerramento ou posições GPS.
- GTFS vigente por dia, hash e vigência; ausência e ambiguidade são explícitas.
- Dia sem monitoramento mantém percentual desconhecido; dia monitorado sem
  ciclos mostra SEM_DADOS e o silêncio identificado, sem virar zero ônibus.
- Carregamento, erro/timeout e nova tentativa. Falha de API não vira relatório
  zerado nem troca silenciosamente para demonstração.
- Layout conferido em desktop e celular; sem rolagem horizontal da página.

## Extensão compatível da API

Campos originais preservados. Em `dias[].lacunas[]`, foram acrescentados:

| Campo | Significado |
|---|---|
| `inicio_no_dia` | Maior entre início real e meia-noite do dia |
| `fim_no_dia` | Menor entre fim real (ou instante observado), fim do dia e instante observado |
| `continua_do_dia_anterior` | Evento começou antes desse dia |
| `continua_no_dia_seguinte` | Intervalo observado ultrapassa a próxima meia-noite |

O array global `lacunas` continua sem fragmentar eventos. O frontend também
consegue recortar a resposta anterior da US13-T02 usando os limites das
janelas e `periodo.observado_ate`, facilitando integração independente.

## Reproduzir os cenários sem tocar na Aiven

1. No backend, com as dependências instaladas:

```powershell
python -m scripts.demonstrar_qualidade_us13
```

2. No frontend:

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

3. Abrir:
`http://127.0.0.1:5173/qualidade.html?inicio=2026-11-17&fim=2026-11-20`.

4. Selecionar 18/11: falha HTTP 503 das 23:50 às 24:00, com GTFS A. Selecionar
   19/11: mesmo evento das 00:00 às 00:20, com GTFS B. O intervalo original
   18/11 23:50 → 19/11 00:20 fica visível nos dois dias.
5. Selecionar 20/11: dia inteiro sem ciclos, silêncio aberto e versões B/C
   sobrepostas. Selecionar 17/11: não observado e sem GTFS, percentual desconhecido.
6. Parar o servidor sintético, consultar de novo e conferir a mensagem de erro.
   Reiniciar o servidor e clicar Tentar novamente: o relatório volta.

O script substitui a conexão por SQLite em memória, fica só em localhost e
marca a resposta com `simulado: true`; a página exibe o aviso. Não escreve
falhas na Aiven nem chama fontes externas. Encerrar ambos os servidores com
Ctrl+C após o ensaio.

Nesta máquina, o Python do `.venv` antigo foi removido antes desta tarefa.
Foi preparado um ambiente isolado em `instance/us13/venv`, ignorado pelo Git,
sem modificar `.env` ou o ambiente antigo. Para reproduzir aqui, substituir
`python` por `./instance/us13/venv/Scripts/python.exe` no backend, ou
`../SprintTimeMarrom-BackEnd/instance/us13/venv/Scripts/python.exe` no frontend.
