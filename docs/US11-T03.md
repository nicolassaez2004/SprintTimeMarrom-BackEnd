## Documentação pública que acompanha a API

| Recurso | Conteúdo |
| --- | --- |
| `GET /docs/indicadores` | Guia HTML com URL, filtros, resposta, paginação, tratamento de 429 e resultado/limites do ensaio |
| `GET /docs/indicadores/openapi.yaml` | Contrato versionado com consultas, documentação pública, cabeçalhos e resposta 429 |
| `GET /docs/indicadores/ensaio.json` | Registro completo das 100 amostras e do ambiente do ensaio |

Essas rotas são públicas e não consomem a cota de consultas. Os exemplos são
texto para copiar, sem executar consultas automaticamente ao abrir o guia.
`/docs` e `/openapi.yaml` na raiz continuam sem uma interface automática.

O [guia HTML](indicadores.html) mostra exemplos de curl, JavaScript e Python,
incluindo filtros de linha/indicador/período, paginação, resposta com unidade,
versão e qualidade, e nova tentativa limitada a três pedidos em caso de 429.
O cliente deve aguardar os segundos de `Retry-After`; 400/503 não são tratados
como uma resposta válida vazia. O código Python usa apenas a biblioteca padrão.
No navegador, a origem precisa ser autorizada pelo CORS da instalação.

Exemplos com `page_size=20`, para que o tamanho da resposta corresponda à URL:

```sh
curl -i 'http://localhost:5000/indicadores?linha=8000&indicador=pontualidade&page=1&page_size=20'
curl -i 'http://localhost:5000/series?linha=8000&indicador=pontualidade&inicio=2026-11-23T00:00:00Z&fim=2026-11-24T00:00:00Z&page_size=20'
```

No Windows PowerShell, usar `curl.exe` se `curl` estiver definido como alias.
Se não houver indicadores publicados, a resposta continua 200, com `dados: []`
e `paginacao.total=0`. As respostas preenchidas do guia são identificadas como
exemplos; não representam indicadores reais calculados das dependências US14/US23.

Percentil pelo método **nearest-rank**: ordenar as 100 durações e tomar a
posição `ceil(0.95 × N)`, com posições a partir de 1. Não há remoção de falhas
ou amostras lentas; todos os pedidos planejados foram registrados e tiveram
resposta 200. Não houve aquecimento HTTP; o cache do sistema operacional não
foi esvaziado após a preparação da base.

O tempo começa antes da conexão TCP e termina após receber todo o corpo;
inclui conexão, fila, limitador SQL, consulta, serialização e transporte local.
O parsing JSON do cliente não é cronometrado. **Não usa Flask `test_client`**
para medir latência. Os dois processos atendem em sockets reais, com alternância
de portas pelo cliente. Não há proxy/balanceador no ensaio.

## Ambiente e dados

- Windows 11, build 26200; Intel64 Family 6 Model 154 Stepping 3; 16 CPUs lógicas.
- Python 3.13.9, Flask 3.1.3, Werkzeug 3.1.9, SQLAlchemy 2.1.9.
- SQLite 3.50.4 em arquivo local, modo WAL, compartilhado entre os processos.
- Dois processos WSGI Werkzeug com threads, sem debug, TLS ou recarregamento.
- Quatro clientes HTTP simultâneos, cada um com IP real de loopback
  (`127.0.0.2` a `127.0.0.5`), 25 chamadas por IP. Nenhum cabeçalho de IP foi
  usado para obter cotas adicionais. O limitador da T02 permaneceu ativo.
- Dados exclusivamente sintéticos: duas linhas (`8000`, `9000`), indicadores
  `pontualidade` e `espera_media`, 100.000 janelas distintas de 60 segundos,
  conjunto `ensaio-us11-v1`, com unidade e qualidade declaradas.
- O script cria somente as tabelas necessárias em um SQLite novo; não gera
  nem publica indicadores operacionais na Aiven.

## Limite verificado também por HTTP

Uma etapa funcional separada, fora da amostra de latência, alternou pedidos
entre os mesmos dois processos usando o IP real `127.0.0.9`:

1. As primeiras 60 chamadas responderam 200.
2. A 61ª respondeu **429**, com `Retry-After: 31` no instante do ensaio.
3. Um IP diferente (`127.0.0.10`) respondeu 200.
4. O script aguardou a virada **real** da janela, sem alterar relógio nem
   limpar contadores. O mesmo IP voltou a responder 200, saldo 59.

O `X-Forwarded-For` foi alterado arbitrariamente nesses 61 pedidos, sem mudar
a identidade da conexão ou burlar a cota. Esses pedidos funcionais não foram
misturados com as 100 medições de latência nem usados para esconder 429 da amostra.

## Repetir o ensaio

Com as dependências instaladas e o ambiente virtual ativo, na pasta do backend:

```powershell
python -m scripts.medir_api_indicadores --saida instance/us11-t03-revisao
```

A pasta de saída deve ser **nova**; o script recusa sobrescrever uma execução.
Cria o SQLite e 100 mil valores sintéticos, sobe dois processos HTTP locais,
executa 100 consultas e a verificação de cota/nova janela e encerra os processos.
Pode aguardar até uma janela para verificar o retorno após 429. Só aceita um
diretório local de saída; não recebe URL de banco compartilhado.

Retorno `0`: p95 ≤ 2 s, todas as amostras 200 e verificações funcionais atendidas.
Retorno `2`: meta/verificação não atendida, preservando o resultado. Erros de
preparação são falhas, sem percentil zero ou resultado inventado. O JSON deve
ser revisado antes de substituir a evidência versionada; a execução não altera
automaticamente os números publicados nesta documentação.

O ensaio original está preservado localmente em
`instance/us11-t03-http-20261123/`, fora do Git. A cópia do resultado acima
contém cada duração, tamanho de resposta, rota, worker, status e todos os
metadados utilizados nesta descrição.
