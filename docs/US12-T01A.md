## Instalação pronta neste computador

- Pasta do servidor: `%LOCALAPPDATA%\TimeMarrom\mysql` (fora do repositório).
- Não é um serviço do Windows e não inicia automaticamente ao ligar o PC.
- Iniciar pelo PowerShell: `& "$env:LOCALAPPDATA\TimeMarrom\mysql\iniciar-mysql.ps1"`.
- Parar pelo PowerShell: `& "$env:LOCALAPPDATA\TimeMarrom\mysql\parar-mysql.ps1"`.
- Credenciais administrativas e dos dois usuários: arquivo local `%LOCALAPPDATA%\TimeMarrom\mysql\credenciais-locais.json`. Não anexar esse arquivo no Trello.
- Conexões cadastradas: **Time Marrom - desenvolvimento** (`marrom_dev`, base `sptrans_dev`) e **Time Marrom - teste** (`marrom_test`, base `sptrans_test`). Host `127.0.0.1`, porta `3306`.
- Para conectar no Workbench, abra o arquivo de credenciais local, copie somente a senha do usuário da conexão e cole na janela de senha. Opcionalmente marque salvar no cofre. O arquivo `.env` já usa essas senhas na aplicação.
- Não repetir instalação, bootstrap ou criação de usuários: esta parte já foi executada. As seções seguintes documentam a preparação para outras máquinas.
- O servidor atende apenas este computador. Cada colega precisará preparar seu próprio ambiente local ou combinar depois uma hospedagem compartilhada.

## 1. Ter um servidor disponível

Se o time já usa um servidor, peça ao responsável host, porta, usuário e acesso às bases abaixo. Receba a senha em particular e preencha somente no computador. Se for local, instale e configure MySQL Server compatível com o projeto (README: 8.0.16+), com InnoDB. O Workbench instalado é o cliente; ele precisa se conectar a um servidor.

## 2. Criar as bases pelo Workbench

1. Abra o Workbench. Ao lado de **MySQL Connections**, clique em **+**.
2. Connection Name: `Time Marrom - administração`. Method: **Standard TCP/IP**. Hostname/Port: os dados do servidor (local usual: `127.0.0.1`, `3306`). Username: usuário autorizado a criar bases.
3. Clique **Test Connection**, digite a senha localmente e salve a conexão.
4. Abra a conexão. Em **File > Open SQL Script**, escolha `scripts/sql/preparar_bases.sql` deste repositório.
5. Execute o script inteiro pelo raio. Registre o resultado de `mysql_server_version` e `engine_padrao` (esperado: InnoDB).
6. Confira os resultados: `sptrans_dev` e `sptrans_test`, ambas com `utf8mb4`. No painel **Schemas**, clique em atualizar para vê-las.
7. Se as bases já existiam com outro charset ou tabelas fora do InnoDB, peça revisão antes de alterar. O script preserva bases existentes.

Base não tem engine: suas tabelas têm. A verificação da aplicação exige InnoDB como padrão e nas tabelas existentes e exercita uma tabela temporária InnoDB. As tabelas de negócio serão criadas pelas migrações da US12-T01B.

## 3. Preparar as conexões do projeto

O administrador deve fornecer usuário(s) autorizados a ler/gravar somente as bases necessárias. Para a verificação também é necessário CREATE TEMPORARY TABLES; migrações exigem permissões DDL adicionais. Não use a conta administrativa na aplicação do time.

1. Na raiz deste backend, copie `.env.example` para `.env`. No PowerShell: `Copy-Item .env.example .env` (apenas se ainda não existir).
2. Preencha `DATABASE_URL` com a base `sptrans_dev` e `TEST_DATABASE_URL` com `sptrans_test`, no mesmo servidor. Preserve `?charset=utf8mb4`.
3. No trecho da senha da URL, caracteres especiais devem estar codificados: `@` vira `%40`, `#` vira `%23`, `%` vira `%25`. Não publique a URL preenchida no Trello ou no Git.
4. O `.gitignore` já ignora `.env` e `.env.*`, mantendo apenas `.env.example` sem segredos.

`TEST_DATABASE_URL` é lida pelo verificador; os testes atuais continuam com sua configuração SQLite. Esta tarefa não muda automaticamente a suíte para MySQL.

## 4. Conferir pela própria aplicação

No terminal, dentro deste backend, com Python 3.10+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.verificar_bases_mysql
```

O script usa `create_app()` e o `db.engine` da aplicação para conectar separadamente às duas bases. Confere versão, nome, charset, engine e escrita/leitura de acentos e emoji em tabela temporária; não cria tabelas permanentes nem executa migrações. A saída esperada contém duas linhas `OK`, uma por base. `/health` sozinho não comprova conexão MySQL.

## 5. Cadastrar as duas conexões de uso no Workbench

Repita o botão **+** para `Time Marrom - desenvolvimento` e `Time Marrom - teste`, com host/porta/usuário fornecidos. Preencha **Default Schema** respectivamente com `sptrans_dev` e `sptrans_test`. Faça **Test Connection** nas duas. Duas bases podem morar no mesmo servidor; não precisa instalar dois servidores.
