# US28-T04 — Extração mensal medida sem bloquear os painéis

Comando (MySQL local isolado; a URL vem do ambiente, nunca do repositório):

```bash
pip install -r requirements-medicao.txt
US28_MEDICAO_MYSQL_URL=mysql+pymysql://root:***@127.0.0.1:3306/us28_medicao \
  python -m scripts.medir_extracao_us28
```

Script: [scripts/medir_extracao_us28.py](../scripts/medir_extracao_us28.py). Resultado completo:
[docs/evidencias/US28-T04-medicao.json](evidencias/US28-T04-medicao.json).

## Ambiente e volume

| Item | Valor |
|---|---|
| Banco | MySQL 8.0.46 local, base isolada `us28_medicao`, buffer pool de 128 MB, todas as migrações (cabeça `us28_0029`). Nunca a Aiven |
| API | waitress (WSGI de produção), processo separado, 16 threads |
| Worker | `python -m app.jobs --tipo EXTRACAO_BRUTOS`, outro processo |
| Volume disponível | 5.356.800 registros em outubro/2026 (1,88 GB com índices), 89.280 ciclos de 30 s |
| Dimensionamento | Coleta real de 26/11/2026: a linha mais movimentada (516) teve 30 veículos por ciclo. A linha pedida tem 30 veículos/ciclo o mês inteiro (pior caso), mais 30 posições de outras linhas por ciclo |
| Dados | SINTÉTICOS, marcados em `payload.sintetico` |

## Extração de um mês de uma linha (Parquet)

| Medida | Resultado |
|---|---|
| `POST /api/extracoes` (202) | 65,7 ms |
| Pedido até `pronto` (consultando `GET /api/extracoes/{id}`) | **147,7 s** |
| Pedido até arquivo baixado | **148,0 s** (meta: 15 min) |
| Registros: SQL esperado / informado pela API / lidos no arquivo | 2.678.400 / 2.678.400 / 2.678.400 ✔ |
| Arquivo | 76,2 MB, download em 0,29 s |
| Estados observados | `processando` (0,6 s) → `pronto` (147,7 s); nunca `pronto` antes do arquivo |

**Consultas durante a extração:** 10 usuários simulados, cada um com IP próprio, consultaram
`/health`, `/api/saude`, `/posicoes/atuais`, `/api/extracoes/{id}` e
`/downloads/indicadores/metadados`.

> **Correção (27/11/2026):** na execução registrada, o waitress subiu sem a opção de proxy
> confiável. Por isso descartou o `X-Forwarded-For` e todos os usuários chegaram como
> `127.0.0.1`, e não com IP próprio. Os números continuam válidos: não houve nenhum 429 e a
> única rota consultada com cota por IP (`/api/saude`) ficou abaixo de 60/min. O script agora
> passa `--trusted-proxy=127.0.0.1 --trusted-proxy-headers=x-forwarded-for`, como no ensaio
> da US27.

| | Consultas | Falhas | p50 | p95 |
|---|---|---|---|---|
| 20 s antes, sem extração | 46 | 8 (*) | 339 ms | 16,3 s |
| Durante a extração | 340 | **0** | 467 ms | 14,3 s |

(*) As 8 "falhas" da linha de base são 404 esperados: antes do pedido, a consulta usa um id
inexistente.

A extração não derrubou nem travou a API: todas as consultas foram atendidas e cada rota ficou
com tempo parecido com e sem extração (`/posicoes/atuais` p95 de 2,3 s → 2,0 s; `/health` de
0,2 s → 0,5 s).

**Problema encontrado (fora desta tarefa):** `/api/saude` leva **16–17 s** com um mês de ciclos,
com ou sem extração. É o que puxa o p95 acima. Fica registrado para a US30/US27.

## Ensaio de reinício (separado; CSV do mesmo mês)

1. Worker encerrado à força (TerminateProcess) depois de gravar 10.000 registros.
2. A API continuou informando `processando`: a reserva ainda valia.
3. Novo worker iniciado. Ele assumiu o pedido quando a reserva de 15 min (valor do produto)
   venceu e gerou o arquivo de novo.
4. Da queda até `pronto`: **1.179 s (19,7 min)** = 15 min de reserva + ~4,6 min de geração do
   CSV (884 MB).
5. Contagem: 2.678.400 esperados = 2.678.400 lidos ✔.
6. Histórico do job: tentativa 1 `INTERROMPIDA` (`ReservaExpirada`, 10.000 registros) →
   tentativa 2 `PRONTO`.

**Conclusão:** recuperação demonstrada, sem duplicar e sem pedido novo. Depois de uma queda, o
tempo até o arquivo é o da reserva mais o da geração, e passa dos 15 min. A meta de 15 min vale
para a extração sem falha.

**Limites:**
- Medido em MySQL local, não na Aiven: ela está somente leitura e sem as migrações `us28_*`.
- A linha pedida tem o volume da linha mais cheia observada, mas a tabela tem 5,4 milhões de
  registros. Um mês real da frota inteira tem perto de 1 bilhão; o índice `(linha_origem,
  coletado_em, id)` faz o custo depender só dos registros da linha pedida.
